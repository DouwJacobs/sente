# Implemented architecture

## Runtime

React 19 + TypeScript + Vite static frontend. Go 1.27.1 standard net/http JSON API at /api and static file serving. Pure-Go modernc SQLite driver avoids CGO in the final container. Bcrypt password hashing and UTF-8/Windows-1252 import decoding use Go x/crypto and x/text.

Production consists of one non-root Go service in a read-only Docker container. Named volumes store the local SQLite database and snapshots. PUBLIC_URL identifies the browser-facing origin; HTTPS enables secure session cookies. A reverse proxy handles TLS.

## Backend boundaries

- app.go: connection/migration initialization, authentication/session middleware, JSON errors, origin/CSRF checks and routes.
- setup.go: same-origin first-run status and token-protected, transactional administrator/session bootstrap; closes permanently when an administrator exists.
- accounts.go: users, account management/grants, categories, description rules, password changes. Category popularity counts distinct transactions from authorized accounts only.
- spending_groups.go: authenticated group listing and household-member creation/editing, optimistic versions and audit history.
- parser.go: exact cents conversion, safe in-memory ZIP expansion, FNB CSV/OFX adapters.
- imports.go: persistent staging, duplicate annotation, commit, provenance and history.
- transactions.go: authorized listing/editing, allocations, approval, assignments, transfer links and audit access.
- budgets.go: periods/preview tokens, targets/settings, dashboard aggregation.
- backup.go: exclusive process lock, snapshots, retention, scheduler and offline restore.

Adapters produce ParsedFile and SourceRow values, independently of review and ledger persistence. No source CSV/OFX files are tracked.

## Persistence and correctness

Bootstrap SQL is embedded from internal/app/schema.sql; migration 2 adds user controls and indexed duplicate fingerprints; migration 3 adds spending_groups and a nullable transaction spending_group_id, preserving existing categories, limits, and transactions. Default groups are seeded once and subsequent migrations/restarts preserve edits. SQLite uses foreign keys, WAL, one pooled connection, and short serialized write transactions. Transaction, account, and period versions reject stale writes; period previews additionally fingerprint affected transaction state.

Users have explicit budget membership. Household membership grants editor access only to household accounts. Private-account access requires grants even for administrators. Administrative account-management metadata excludes balances/transactions.

Transaction source_date/source_amount/source_description, FITID, import linkage, and provenance are immutable through the API. Editable fields and allocations are separate. Approval records user/time; edits invalidate review. Audit details are stored in the database without logging financial content.

Budget totals use allocations, cash movement uses parent transactions, and transfer principal is excluded. Dashboard default scope is household only. Explicit account selection uses account-specific reporting and removes shared limit comparison; private accounts use the selected period as a date filter.

## Frontend

Shared tokens live in web/src/styles.css; shared button/field/form/badge/modal primitives live in web/src/ui.tsx. API calls centralize CSRF, same-origin credentials, session expiry, and JSON errors. Shared Field/Form validation uses first blur to reveal inline accessible errors, then updates while editing; dependent validators re-run with related values, and submission blocks invalid requests and focuses the first invalid field. Local storage contains theme preference only.

Use make dev (scripts/dev.py) for Vite HMR on 127.0.0.1:5173 and a watched Go backend on port 8081. The runner proxies /api without changing the browser origin, sets PUBLIC_URL to the dev frontend origin, keeps a separate persistent development database, and restarts Go after successful builds. Production uses the built web/dist. Playwright starts an isolated synthetic-data service through scripts/e2e-server.py. The browser-test server is never a production database.

## Operations

Snapshots use SQLite VACUUM INTO with integrity checks. Fourteen snapshot files are retained; successful backup status and automatic failure status are exposed to administrators. Restore runs offline under the database lock, preserves the previous database, checks integrity/schema version, and clears sessions.

README documents startup, Docker, proxy settings, backup, restore, and password recovery. A second overlapping FNB OFX sample remains necessary to validate ID stability.

## Local FNB accounts/balance connection

Migration 5 adds accounts.sync_hidden, fnb_connections and fnb_discoveries. fnb_connection.go offers owner-scoped admin connection/refresh/schedule/visibility routes, AES-256-GCM encrypted credential blobs and a generated 0600 runtime key under the OS config directory (override FNB_KEY_FILE with an absolute path outside workspace/backups). No credential read endpoint or audit payload. Existing ciphertext without its key fails without creating a replacement key.

The Go service launches connectors/fnb/owner/refresh.mjs with credentials on stdin and a bounded strict JSON stdout contract; stderr is discarded. Windows Node/Chrome are used from this Ubuntu WSL dev checkout, using UNC source paths; Linux Node/installed Chrome work when configured. FNB_NODE_EXECUTABLE/FNB_RUNNER_PATH override executables/script paths; no bank credentials in environment/arguments. Temporary incognito profiles live in OS temp and are removed on normal completion. Forced kills may require owner cleanup.

Both refresh types default to headless; saved debug mode shows the browser for owner observation/approvals. Login uses vetted legacy selectors and one bounded attempt, validates FNB origin/form target before typing, then navigates only Accounts. Account names/full numeric IDs and current ledger decimal balances are normalized without floats. Unsupported IDs are counted/skipped; missing balances preserve previous tracker snapshots; unexpected money/layout fails atomically. Available balance/rewards are not substituted for ledger balance. Current login/approval/ledger DOM compatibility remains owner-test dependent.

Runs serialize across connections, recheck owner/account permissions at commit, retain hidden choices and sharing, and never create ledger/import rows. Next due advances after durable success, errors suspend scheduling, and startup marks interrupted jobs as requiring action. Scheduler scans every minute, requires an active admin owner, and provides configurable off/6/12/24/168 hour intervals. Normal views/aggregates exclude sync_hidden accounts; stored history remains intact.

The current Docker image deliberately excludes Node/connector sources and is not configured for this local WSL connector. Deployment requires explicit browser/runtime and external key persistence configuration; local dev is the current supported runtime. Same-host encryption is not a technical barrier against an unrestricted agent.

## FNB transaction staging (2026-10-03)

POST /api/fnb/transactions is owner-admin/CSRF scoped. Shared runFNB serializes all bank work through the existing lock, decrypts only inside the service and sends exact target bank identities plus a server-generated run ID over stdin. The bridge bounds JSON to 16 MiB and discards stderr; no public worker port. refresh.mjs reuses the existing ephemeral login/approved-origin/logout lifecycle. transactions.mjs adapts vendored navigation/table selectors without importing the old runtime: unique full detail identity, named column checks, posted-history/status evidence, exact dates/BigInt decimals and first page only. Explicit Pending rows are excluded and raw page count preserves truncation warnings. Unknown/ambiguous layout and embedded nonzero fees fail closed. Numeric transaction counters extend the diagnostic allowlist. Total Go timeout is four minutes; worker abort is bounded to 205 seconds plus cleanup.

fnb_transactions.go selects owner discoveries and checks current enabled editor permissions before fetching and again in a single staging transaction. NormalizeFNBReport validates account/currency/run/date/exact money/status. File uploads and live snapshots share stageImport, annotate and commitImport; the live flow adds no direct ledger writer. Canonical snapshot hashes ignore run/balance changes, retain row references and raw page count, and reuse original immutable staged provenance. References remain separate from FITID; overlap fingerprints require human decisions. ParsedFile stores run_id/coverage and SourceRow source_reference; commit retains full ParsedFile metadata and source provenance. No migration is needed for JSON import metadata. Live fetches do not update balance snapshots or last successful balance-refresh timestamp.

Manual fetch creates previews only; no scheduled transaction fetch, automatic commit, approval or complete-history checkpoint. Staged previews survive restart through import history. Interrupted connection jobs retain the existing action-required recovery. Current DOM/posting/fee compatibility is owner-verified only and still unconfirmed. Browser tests can use E2E_TEST_PORT to isolate synthetic services from concurrent test runs.
